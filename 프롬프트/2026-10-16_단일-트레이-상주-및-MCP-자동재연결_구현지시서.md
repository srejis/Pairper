# Pairper — 단일 트레이 상주 앱 및 MCP 자동 재연결 구현 지시서

## 1. 작업 목적

현재 Pairper는 논문 읽기 GUI와 Secure MCP Tunnel 실행기가 분리되어 있다.

사용자는 프로그램을 하나만 실행하고 관리하기를 원한다.

이번 수정에서는 Pairper 애플리케이션 자체가 MCP 연결을 관리하도록 변경한다.

최종 동작은 다음과 같다.

- Windows 로그인 시 Pairper 자동 실행
- 실행 시 로컬 MCP와 Secure MCP Tunnel 자동 연결
- Pairper 창의 X를 누르면 트레이로 최소화
- 창이 숨겨져도 ChatGPT에서 논문 접근 가능
- 프로그램이 연결 상태를 주기적으로 확인
- 연결이 끊어지면 자동 재연결
- 트레이에서 프로그램을 다시 열 수 있음
- 트레이의 'Pairper 종료'를 선택하면 프로그램과 소유한 연결 프로세스 종료

기존 PDF 처리, 논문 데이터베이스, 문서 재구성, React + TypeScript 프론트엔드는 유지한다.

## 2. 기존 구현을 확인할 것

작업 전에 다음 모듈을 읽는다.

- `src/pairper/app/main.py`
- `src/pairper/ui/window.py`
- `src/pairper/ui/bridge.py`
- `src/pairper/tunnel/runtime.py`
- `src/pairper/tunnel/config.py`
- `start-pairper.ps1`
- `start-pairper-tunnel.ps1`
- `install-pairper-autostart.ps1`
- `uninstall-pairper-autostart.ps1`

기존 터널은 `tunnel-client v0.0.16`이고, 로컬 MCP는 Python stdio 방식이다.

이미 ChatGPT에서 `list_papers`, `list_pending_papers`, `get_paper_manifest`, `get_page_image`를 호출해 실제 로컬 데이터 조회에 성공했다.

따라서 기존 연결 프로토콜과 MCP 11개 도구를 불필요하게 변경하지 않는다.

## 3. 전체 아키텍처

최상위 프로세스는 Pairper 데스크톱 애플리케이션이다.

내부 역할을 다음과 같이 분리한다.

**Application Controller**

- 애플리케이션 시작과 종료
- 중복 실행 방지
- 시스템 트레이
- 윈도우 표시·숨김
- 터널 연결 관리자 시작·정지

**Tunnel Supervisor**

- 터널 프로세스 실행
- 프로세스 상태 확인
- health 및 readiness 검사
- 연결 끊김 감지
- 재연결 수행
- 오류 상태 및 로그 관리

**Pairper MCP**

- 기존 Python stdio MCP 도구
- PDF, SQLite 및 논문 뷰 접근
- tunnel-client의 자식 프로세스로 실행

**React + TypeScript**

- 논문 목록 및 열람
- 현재 연결 상태 표시
- 연결 진단·재연결 UI

백그라운드 연결을 React 컴포넌트의 생명주기에 종속시키지 않는다.

React 화면이 닫히거나 새로 고쳐져도 MCP 연결은 유지되어야 한다.

## 4. 시스템 트레이

PySide6의 `QSystemTrayIcon`과 `QMenu`를 사용한다.

Windows 알림 영역에 Pairper 아이콘을 표시한다.

다음 메뉴를 제공한다.

1. **Pairper 열기** — 기존 창을 표시하고 앞으로 가져오기
2. **연결 상태** — 현재 터널 연결 및 최근 확인 결과 표시
3. **다시 연결** — 기존 연결을 안전하게 정리한 뒤 재연결
4. **Pairper 종료** — 애플리케이션과 소유한 자식 프로세스를 정상 종료

트레이 아이콘을 더블클릭하면 프로그램 창을 복원한다.

연결 상태에 따라 트레이 툴팁을 변경한다.

아이콘 자체의 세부 디자인은 현재 UI 스타일과 일관된 간단한 것으로 구현한다.

### 창 닫기

기존 `MainWindow.closeEvent()`는 종료 처리를 수행한다.

이 동작을 변경한다.

사용자가 X 버튼을 누르면 이벤트를 무시하고 창을 숨긴다.

단, 트레이의 'Pairper 종료'를 선택한 경우에는 실제 종료 처리를 허용한다.

숨긴 상태에서 타이머와 터널 관리 기능이 중단되어서는 안 된다.

`QApplication.setQuitOnLastWindowClosed(False)`를 적용한다.

트레이 사용 불가능 환경에서는 창을 숨겨 복원이 불가능해지지 않도록 정상 종료나 사용자 안내로 안전하게 대체한다.

### 명시적 종료

종료 시 다음 순서를 지킨다.

1. 재연결 시도 중단
2. 터널 관리 작업 취소
3. Pairper가 소유한 tunnel-client 종료
4. 해당 MCP 자식 프로세스 종료 확인
5. SQLite 및 기타 리소스 정리
6. 트레이 아이콘 제거
7. QApplication 종료

사용자가 추가한 원본 PDF와 저장된 논문 뷰는 삭제하지 않는다.

다른 프로젝트의 터널 프로세스를 종료하지 않는다.

## 5. 연결 관리자 구현

현재 `pairper.tunnel.runtime`에 있는 다음 기능을 최대한 재사용한다.

- `.env` 로딩
- 터널 프로필 검증
- 파일 잠금을 이용한 중복 실행 방지
- `tunnel-client` 실행
- Windows Job Object 관리
- `/healthz`, `/readyz` 확인
- 로그 및 상태 파일 관리
- API 키 마스킹

새로운 TunnelSupervisor를 별도 모듈로 구성한다.

예:

`src/pairper/tunnel/supervisor.py`

메인 GUI 스레드에서 장시간 실행 명령을 동기적으로 호출하지 않는다.

터널 프로세스 실행·대기·재연결은 별도의 작업 스레드에서 처리한다.

Qt UI에는 Signal을 이용해 상태 변경만 전달한다.

### 상태 모델

최소 상태는 다음과 같다.

- `not_configured`
- `connecting`
- `connected`
- `disconnected`
- `reconnecting`
- `authentication_failed`
- `error`
- `stopped`

`connected`는 터널 런타임이 준비되었다는 뜻이다.

ChatGPT에서 실제 도구를 호출한 사실은 별도 기록으로 유지한다.

로컬 `/readyz` 성공만으로 ChatGPT 연결 전체가 검증됐다고 표시하지 않는다.

## 6. 주기적 상태 확인

터널 연결 상태를 백그라운드에서 **10초 간격**으로 확인한다.

다음 정보를 확인한다.

- 관리 중인 터널 프로세스 생존 여부
- 로컬 `/healthz` 응답
- 로컬 `/readyz` 응답
- 최근 상태 변경 시간
- 최근 터널 도구 호출 기록

상태 확인 시 UI가 멈추지 않아야 한다.

장시간 응답이 없는 검사에는 타임아웃을 적용한다.

연결이 정상적이면 기존 세션을 유지한다.

정상 연결 상태에서 불필요하게 터널을 다시 시작하지 않는다.

일시적인 검사 실패 한 번으로 바로 터널을 종료하지 않고, 짧은 연속 실패 기준을 적용해 연결 끊김을 판정한다.

## 7. 자동 재연결

프로세스가 종료되거나 readiness를 지속해서 잃으면 재연결한다.

재연결 정책은 다음과 같이 한다.

- 첫 재시도: 약 3초 후
- 이후 재시도: 5초, 10초, 20초, 40초
- 최대 간격: 60초
- 계속 실패하면 60초 간격으로 상태를 확인하고 재시도

여기에 소폭의 지터를 적용해 반복적으로 같은 시점에 요청이 집중되지 않도록 한다.

정상 연결이 일정 시간 유지되면 재시도 횟수를 초기화한다.

다음 상황에서는 자동 재시작을 멈추고 사용자 조치를 기다린다.

- API 키가 유효하지 않음
- 터널 사용 권한 부족
- Tunnel ID 오류
- 필수 설정 파일 누락
- Python 실행 파일 또는 터널 실행 파일 누락

이러한 영구 오류를 네트워크 일시 장애와 구분한다.

사용자가 트레이의 '다시 연결'을 선택하면 설정을 재검사한 후 수동 복구를 시도할 수 있어야 한다.

재연결 중 기존 프로세스가 남아 중복 터널이 생성되는 문제를 방지한다.

## 8. 기존 터널 자동 시작과의 충돌 해결

현재는 `Pairper MCP Tunnel`이라는 Windows 작업 스케줄러 등록을 지원한다.

이전 설계에서는 Windows 로그인 시 터널 실행기만 시작했다.

새 설계에서는 **Pairper 애플리케이션 전체를 시작**해야 한다.

따라서 자동 시작 대상을 변경한다.

새 작업 이름:

`Pairper`

동작:

Windows 로그인 → Pairper 실행 → 트레이 상주 → 터널 자동 연결

기존 `Pairper MCP Tunnel` 작업이 등록되어 있는지 확인한다.

기존 작업이 명확히 Pairper 프로젝트 소유이며 사용자가 전환을 승인한 경우에만 제거하거나 비활성화한다.

다른 프로젝트의 작업이나 소유권이 불분명한 항목은 수정하지 않는다.

작업 스케줄러 등록과 이전 작업 전환은 사용자에게 변경 내용을 제시하고 명시적으로 설치 명령을 실행했을 때 수행한다.

자동 시작 작업에 비밀 API 키를 저장하지 않는다.

작업 스케줄러가 중복 Pairper 프로세스를 실행하지 않도록 한다.

프로세스 비정상 종료 시 작업 스케줄러를 통한 재시작과 앱 내부 터널 재연결을 구분한다.

## 9. 프로그램 단일 실행

사용자가 이미 Pairper를 실행하고 있을 때 다시 실행 파일을 열면 새 앱 인스턴스와 터널을 중복 생성하지 않는다.

기존 Pairper 창을 복원하고 앞으로 가져온다.

단일 실행은 로컬 IPC 또는 적절한 프로세스 잠금으로 구현한다.

단순히 프로세스 이름만 검색하여 종료하는 방식은 사용하지 않는다.

정상 Pairper 인스턴스를 종료하지 않고 기존 창을 활성화할 수 있어야 한다.

## 10. 설정 및 보안

현재 프로젝트 `.env`를 계속 사용한다.

- `CONTROL_PLANE_API_KEY`
- `CONTROL_PLANE_TUNNEL_ID`
- `PAIRPER_DATA_DIR` — 선택 사항

이미 존재하는 실제 키와 Tunnel ID는 유지한다.

사용자가 다시 키를 입력하도록 요구하지 않는다.

키를 전역 환경변수에 저장하지 않는다.

React 프론트엔드나 WebChannel 응답에 비밀값을 포함하지 않는다.

연결 상태 표시에는 안전한 상태 정보만 전달한다.

로그에는 API 키, 인증 헤더, 실제 터널 토큰을 출력하지 않는다.

## 11. 사용자 경험

Pairper를 실행하면 논문 목록 화면을 표시한다.

동시에 백그라운드에서 터널 연결을 시작한다.

프로그램은 연결이 진행되는 동안에도 정상적으로 사용할 수 있어야 한다.

사용자가 X 버튼을 누르면 창을 숨기고 트레이에 남는다.

이때 최초 1회 다음과 같은 안내를 제공해도 된다.

"Pairper가 시스템 트레이에서 계속 실행됩니다. 종료하려면 트레이 아이콘의 'Pairper 종료'를 선택하세요."

반복적인 알림은 표시하지 않는다.

React 상단의 연결 상태는 Qt 백그라운드 관리자가 보내는 데이터를 사용한다.

연결이 끊긴 경우 화면에 현재 상태를 표시하지만, 이미 저장된 논문을 읽는 기능은 계속 사용할 수 있어야 한다.

## 12. 테스트 항목

다음 시나리오를 반드시 검증한다.

### 애플리케이션

- Pairper를 실행하면 논문 목록 창이 열린다.
- 실행 후 터널이 자동으로 연결된다.
- X 버튼을 누르면 창만 숨겨진다.
- 트레이 아이콘이 유지된다.
- 트레이에서 창을 다시 연다.
- 프로그램을 다시 실행하면 기존 창이 복원된다.
- 트레이에서 종료하면 실제로 프로세스가 종료된다.

### MCP 연결

- 창을 숨긴 상태에서도 `list_papers`가 작동한다.
- 프로그램을 열어둔 상태에서 터널 연결을 끊으면 자동으로 복구된다.
- 일시적인 네트워크 장애에서 재연결된다.
- API 키 오류에서는 무한 재시도하지 않는다.
- 복구 후 논문 데이터가 유지된다.
- 두 개 이상의 터널 실행기가 동시에 생성되지 않는다.

### Windows 자동 시작

- 현재 사용자 로그인 시 Pairper 앱이 실행된다.
- 사용자가 원한 대로 창을 강제로 표시하지 않고 트레이에서 시작할 수 있다.
- MCP가 별도 조작 없이 연결된다.
- 이전 터널 전용 자동 시작 작업과 중복되지 않는다.
- 자동 시작을 해제해도 일반 Pairper 실행은 가능하다.

### 회귀 검증

- 기존 Python 테스트 통과
- 기존 React/TypeScript 테스트 통과
- PDF 추가 및 중복 방지 유지
- SQLite 데이터 보존
- 기존 MCP 11개 도구 유지
- 문서 블록 렌더링 유지
- 수식·표·이미지 원본 fallback 유지

## 13. 완료 기준

다음 동작을 완료 목표로 한다.

**Windows 로그인 → Pairper 트레이 자동 실행 → MCP 자동 연결 → ChatGPT에서 논문 조회 → 창을 열어 논문 읽기 → X로 숨기기 → 연결 유지 → 장애 시 자동 재연결**

사용자는 터널용 콘솔 창을 따로 유지할 필요가 없어야 한다.

단, 트레이 상주와 자동 재연결이 구현됐다는 사실만으로 원격 연결 전체의 정상 동작을 단정하지 않는다.

실제 ChatGPT 호출과 로컬 상태를 함께 확인한다.

테스트 결과에는 사용한 실행 방식, 관측된 프로세스 상태, health/readiness 결과, MCP 호출 결과, 실패 및 복구 여부를 각각 기록한다.

기존 코드와 저장된 논문 데이터를 보존하면서 작업을 진행한다.
