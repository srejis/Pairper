# Pairper 2단계 — 한국어 해석 품질 극대화를 위한 다중 에이전트 반복 실험

## 1. 최종 목표

Pairper의 2단계인 **외국어 논문의 한국어 해석 품질을 최대한 높이는 것**이 이번 작업의 최종 목표다.

여기서 해석은 외국어를 한국어로 변환하는 번역 작업이다. 사용자의 배경지식을 고려한 설명, 쉬운 풀이, 개념 해설, 비유, 추가 정보 제공은 포함하지 않는다. 이러한 기능은 별도의 3단계에 속한다.

번역에서 가장 중요한 기준은 **원문에 존재하는 정보가 변환 과정에서 최대한 훼손되거나 소실되지 않는 것**이다.

원문의 주장, 조건, 예외, 부정, 불확실성, 인과관계, 수치, 단위, 수식, 표, 전문용어, 인용, 논리적 관계를 정확하게 보존해야 한다.

자연스러운 한국어를 추구하되, 자연스러움을 이유로 정보를 생략하거나 의미를 변경하지 않는다.

**현재 구현된 방식이나 기존 아키텍처를 유지하는 것보다 최종 해석 품질을 높이는 것이 우선이다.**

필요하다면 1단계 PDF 재구성, 구조화 데이터, 추출 과정, 검증 방식까지 개선할 수 있다. 단, 기존 원문의 보존과 정확성은 훼손하지 않는다.

## 2. 에이전트 운영 구조

메인 에이전트 1개와 서브 에이전트 3개를 운영한다.

### 메인 에이전트 — 실험 총괄 및 품질 관리

메인 에이전트의 핵심 책임은 직접 하나의 해결책에 집중하는 것이 아니라 **전체 실험을 관리하고 에이전트 간 발견을 결합해 해석 품질을 지속적으로 발전시키는 것**이다.

담당 업무:

- 프로젝트의 기존 의도와 현재 구현을 파악한다.
- 최초에 검증할 서로 다른 가설 3개를 선정한다.
- 각 서브 에이전트에 가설 하나씩 배정한다.
- 가설의 검증 가능성과 실험 설계를 검토한다.
- 각 에이전트의 실험 결과와 발견한 문제를 지속적으로 공유시킨다.
- 가설 사이의 공통 원인, 상호보완 관계, 충돌을 분석한다.
- 효과가 검증된 변경사항을 통합하고 전체 논문에서 회귀 검증한다.
- 결과가 좋지 않은 가설을 수정하거나 기각하고 새로운 가설로 교체한다.
- 이전보다 품질을 높일 가능성이 있는 새로운 가설을 능동적으로 탐색한다.
- 충분한 품질에 도달했는지를 실제 검증 근거로 판단한다.

메인 에이전트는 단순히 작업을 분배하고 결과를 취합하는 관리자가 아니다.

**서브 에이전트들이 서로의 연구 결과를 활용하며 더 좋은 방법을 발견하도록 만드는 연구 총괄자**다.

### 서브 에이전트 3개 — 독립적인 가설 실험

동시에 활성화된 가설은 항상 3개를 유지한다.

각 서브 에이전트는 한 개의 주도 가설을 담당한다.

각 에이전트는 다음을 수행한다.

1. 가설을 명확하고 반증 가능하게 정의한다.
2. 현재 프로그램과 원본 PDF의 실제 상태를 조사한다.
3. 기준 해석 결과를 확보한다.
4. 가설을 검증할 실험을 설계한다.
5. 필요한 구현을 수행하고 실행한다.
6. 원문과 한국어 결과를 비교해 품질을 검증한다.
7. 새로운 문제와 기존 문제의 해결 여부를 확인한다.
8. 문제가 있다면 원인을 분석한다.
9. 해결 방법을 조사하고 적용한다.
10. 수정된 결과를 다시 실행하고 검증한다.
11. 모든 발견과 실험 결과를 메인 에이전트 및 다른 에이전트에 전달한다.

한 번 실험했다고 가설 검증이 끝나는 것은 아니다.

가설이 유효하다면 반복적으로 발전시키고, 충분히 개선되지 않거나 더 좋은 대안이 있다면 메인 에이전트의 판단에 따라 교체한다.

## 3. 가설 3개를 유지하는 규칙

**가설 슬롯은 언제나 3개다.**

예를 들어:

- 에이전트 A: 가설 A
- 에이전트 B: 가설 B
- 에이전트 C: 가설 C

가설 A와 B를 결합했을 때 더 좋은 접근이 발견되면 결합을 허용한다.

하지만 이 경우 활성 가설이 2개가 되므로, 메인 에이전트는 새로운 가설 D를 만들어 다시 3개를 유지해야 한다.

가설 하나가 기각되거나 더 이상 개선 여지가 없다면 역시 새로운 가설로 교체한다.

가설은 기존 아이디어를 약간 다르게 표현한 수준이어서는 안 된다. 서로 다른 원인, 개선 기전 또는 검증 관점을 가져야 한다.

새로운 가설은 다음을 바탕으로 도출한다.

- 실제 번역 오류에서 발견된 원인
- 다른 에이전트의 실험 결과
- 기존 방식의 구조적 한계
- 현재 접근으로 해결되지 않은 문제
- 더 높은 정확도를 기대할 수 있는 대안
- 아직 시험하지 않은 독립적인 개선 방향

가설 자체를 유지하는 것이 목표는 아니다.

**더 높은 해석 품질에 도달하기 위해 가설을 지속적으로 교체하고 발전시키는 것이 목표다.**

## 4. 최초 가설 수립

처음부터 특정 번역 알고리즘이나 모델을 정답으로 가정하지 않는다.

메인 에이전트는 현재 Pairper의 코드와 기존 PDF 6편을 조사한 뒤, 해석 품질을 높일 가능성이 있는 가설 3개를 세운다.

초기 조사에서 고려할 수 있는 방향의 예시는 다음과 같다.

- 논문의 넓은 문맥과 전문용어의 일관성을 활용하면 번역 정확도가 높아지는가?
- 1단계에서 보존하거나 제공하는 정보의 질이 번역 오류를 줄이는 데 얼마나 영향을 주는가?
- 번역 후 원문 대조와 오류 수정 과정을 거치면 의미 손실과 왜곡을 얼마나 줄일 수 있는가?

이는 출발점의 예시이지 반드시 채택해야 할 세 가지 정답은 아니다.

실제 데이터를 조사한 결과 더 중요한 문제가 발견되면 그 문제를 해결할 가설을 우선한다.

각 가설에 대해 다음을 기록한다.

- 해결하려는 실제 문제
- 문제가 발생한다고 판단한 근거
- 가설이 맞을 경우 기대하는 개선
- 검증에 사용할 논문과 사례
- 성공 및 실패를 판단할 기준
- 기존 접근과 비교할 방법

## 5. 실험 데이터

현재 Pairper에 등록되어 있는 실제 PDF 논문 **6편 전체**를 실험에 활용한다.

합성 데이터나 짧은 예문만으로 번역 품질을 판단하지 않는다.

실제 6편에 포함된 다양한 논문 구조와 표현을 확인한다.

특히 다음과 같은 콘텐츠가 정확히 해석되는지 살펴본다.

- 제목, 초록, 본문, 결론
- 기술적 전문용어와 약어
- 긴 문장과 복잡한 논리 관계
- 수식과 인라인 수학 표현
- 표와 표 내부의 문장
- 그림 설명 및 캡션
- 알고리즘과 코드 주변의 설명
- 정리, 정의, 증명
- 인용 및 참고문헌
- 여러 문단과 섹션에 걸쳐 이어지는 논리

일부 성공 사례만 선별해서 전체 품질이 좋아졌다고 결론 내리지 않는다.

빠른 가설 탐색에는 대표 사례를 활용할 수 있지만, 최종 개선을 검증할 때는 6편 전체에 적용해 기존의 정상적인 부분이 손상되지 않았는지 확인한다.

## 6. 반복 실험 절차

모든 가설은 다음의 사이클을 따른다.

**가설 → 실행 → 검증 → 문제 발견 → 원인 분석 → 해결 방안 탐색 → 수정 → 재실행 → 재검증**

이 과정은 한 번 수행하는 절차가 아니라 지속적으로 반복하는 핵심 작업 방식이다.

### 문제 발견

번역 결과를 원문과 비교하면서 다음 유형의 오류를 적극적으로 찾는다.

- 원문의 정보가 빠짐
- 원문에 없는 정보가 추가됨
- 주장이나 논리가 달라짐
- 부정문·조건문·예외·가능성의 의미가 바뀜
- 전문용어가 부정확하거나 일관되지 않음
- 숫자·단위·수식·기호가 변형됨
- 표의 행·열 또는 관계가 훼손됨
- 문맥을 잘못 이해해 의미가 달라짐
- 문단 간 참조 관계가 잘못 전달됨
- 원문에 없는 설명이나 해설이 삽입됨
- 한국어 표현이 잘못되어 원문과 다른 의미로 읽힘

이 목록에 없는 새로운 문제도 적극적으로 발견한다.

### 원인 분석

오류가 확인되면 원인을 추측으로 확정하지 않는다.

실제 데이터를 추적해 어느 단계에서 문제가 발생했는지 확인한다.

예를 들어 PDF 추출, 1단계 구조화, 문맥 전달, 번역 수행, 번역 결과 조립, 렌더링 또는 검증의 문제인지 구분한다.

원인에 따라 1단계와 2단계 중 어디를 수정해야 하는지도 판단한다.

### 해결 방법 탐색

처음 떠오른 방법 하나만 시행하지 않는다.

가능한 대안을 조사하고 기존 방식과 비교한다.

변경 이후 좋아진 부분뿐 아니라 나빠진 부분도 확인한다.

가설이 틀렸다면 가설을 수정하거나 폐기한다.

실제로 확인되지 않은 문제를 해결하기 위해 불필요한 기능을 추가하지 않는다.

## 7. 에이전트 간 상호작용

세 에이전트가 완전히 독립적으로 작업만 하고 마지막에 결과를 합치는 방식은 피한다.

**에이전트 간 발견을 계속 교환하는 것이 필수다.**

예시:

에이전트 A가 번역 오류의 원인이 잘못된 문단 경계에 있음을 발견했다면, 이 정보를 에이전트 B와 C에 공유한다.

에이전트 B가 문맥 정보를 개선했지만 특정 수식의 의미가 훼손되는 문제를 발견했다면, 에이전트 A와 C가 각자의 관점에서 해당 현상을 재검토할 수 있도록 한다.

에이전트 C가 검증 중 이전에는 발견되지 않은 오류 유형을 확인했다면, 메인 에이전트는 그 오류를 기존 가설에 반영하거나 새로운 가설을 세울 수 있다.

메인 에이전트는 특히 다음을 수행한다.

- 각 실험의 결과를 다른 실험의 새로운 근거로 사용한다.
- 공통적으로 발견된 문제를 우선순위에 반영한다.
- 두 가설의 개선 효과가 서로를 강화하는지 확인한다.
- 효과가 충돌한다면 원인을 분석하고 통합 방법을 찾는다.
- 단순히 개별 실험의 최고 결과를 고르지 않고, 결합한 시스템 전체의 품질을 확인한다.

동일한 코드나 데이터에 대한 수정 충돌을 방지할 수 있도록 실험 환경과 변경사항을 분리하고, 통합은 메인 에이전트가 관리한다.

## 8. 1단계 수정 허용 범위

2단계 번역 품질에 영향을 주는 문제가 1단계에 있다면 1단계를 수정할 수 있다.

1단계는 기존 방식 자체가 목적이 아니라 좋은 해석을 위한 기반이기도 하다.

예를 들어 원문 재구성 과정에서 번역에 필요한 정보가 누락되거나 관계가 손실되는 실제 문제가 발견되면 이를 해결한다.

다만 다음 원칙은 유지한다.

- 원본 PDF와 원문 데이터 보존
- 정확한 읽기 순서 유지
- 수식·표의 기계 판독 가능한 구조 유지
- 임의적인 내용 생성 및 추측 금지
- 기존 논문 재구성 결과에 대한 회귀 검증
- 원문과 해석 결과의 출처 관계 추적 가능성

1단계 수정의 성공 여부도 **원문의 정확한 보존과 최종 번역 품질의 개선**으로 판단한다.

기존 1단계 구현을 무조건 유지하지도, 필요 없이 전체를 다시 만들지도 않는다.

## 9. 해석 품질 검증

해석 품질은 한국어 문장이 자연스럽다는 이유만으로 좋다고 판단하지 않는다.

**원문 대비 의미 충실도와 정보 보존을 가장 중요한 평가 기준으로 삼는다.**

검증에서는 최소한 다음을 비교한다.

1. 기존 방식의 번역 결과
2. 새로운 가설을 적용한 번역 결과
3. 해당 구간의 실제 원문
4. 번역에서 보존된 정보와 손실된 정보
5. 수정으로 해결된 문제와 새로 생긴 문제

단순히 다른 AI가 번역을 좋다고 평가하는 것만으로 검증을 완료하지 않는다.

원문에 근거한 구체적인 오류와 대조 결과를 확인한다.

가능한 경우 누락, 추가, 의미 왜곡, 전문용어 불일치, 수치·수식·표 오류 등을 유형별로 기록하고 이전 결과와 비교한다.

평가 모델이나 평가 방식에도 오류가 있을 수 있으므로, 평가 결과에 의문이 있으면 원문과 번역문을 다시 직접 대조한다.

개선이 확인되지 않은 변경을 성공으로 기록하지 않는다.

품질이 개선되더라도 기존에 정확했던 표현이 새롭게 잘못 번역된다면 회귀 문제로 취급한다.

## 10. 품질 극대화를 위한 운영 원칙

이번 작업은 정해진 횟수만큼 실험한 뒤 종료하는 것이 아니다.

**메인 에이전트가 더 높은 품질을 기대할 만한 가설이 남아 있다고 판단하면 다음 실험을 계속한다.**

한 번의 성공이나 특정 점수 도달을 최종 완료로 간주하지 않는다.

메인 에이전트는 매 실험 주기 후 다음 질문을 검토한다.

- 아직 해결되지 않은 실제 번역 오류가 있는가?
- 해결했다고 판단한 문제가 다른 논문에서도 재현되는가?
- 현재 방식의 한계는 무엇인가?
- 기존 가설을 개선하거나 결합할 가능성이 있는가?
- 전혀 다른 접근으로 품질을 더 높일 가능성이 있는가?
- 1단계에서 더 좋은 정보를 제공하면 번역 결과가 개선될 수 있는가?
- 현재의 품질 평가가 실제 오류를 놓치고 있지는 않은가?

이 질문에서 유의미한 개선 가능성이 발견되면 다음 가설과 실험으로 연결한다.

명확히 실패한 접근을 근거 없이 반복하지 않는다.

동일한 실험을 반복하면서 결과만 조금 바뀌는 것을 진전으로 취급하지 않는다.

실패한 방법도 왜 실패했는지 기록하고 이후 가설 수립에 활용한다.

### 최종 완료 판단

다음 조건을 종합적으로 충족했을 때 메인 에이전트가 충분한 품질에 도달했다고 판단할 수 있다.

- 6편 전체에 대한 검증이 수행되었다.
- 발견된 중대한 정보 누락과 의미 왜곡 문제가 해결되었다.
- 수치, 수식, 표, 조건, 부정 등 핵심 정보의 손상이 남아 있지 않다.
- 최신 변경으로 발생한 회귀 문제가 없다.
- 반복적인 검증에서도 품질이 안정적이다.
- 실험할 가치가 있는 새로운 개선 가설을 충분히 탐색했고, 추가 가설에서 실질적인 개선이 확인되지 않는다.
- 더 높은 품질을 기대할 만한 구체적인 미검증 문제가 남아 있지 않다.

완료 조건을 충족하지 못했다면 미완료 상태와 남은 문제를 명확히 보고한다.

**단순히 오류가 발견되지 않았다는 것을 오류가 존재하지 않는다는 증명으로 취급하지 않는다.**

## 12. 메인 에이전트의 최종 책임

메인 에이전트의 목표는 서브 에이전트 3개를 성공적으로 실행시키는 것이 아니다.

**세 에이전트를 활용해 단일 접근보다 더 높은 품질의 한국어 해석 시스템을 만드는 것**이다.

이를 위해 지속적으로 다음을 수행해야 한다.

- 가설 발견
- 실험 분배
- 결과 공유
- 문제 발굴
- 원인 분석
- 개선안 비교
- 가설 통합 및 교체
- 코드 변경 통합
- 실제 논문 검증
- 새로운 개선 가능성 탐색

프로젝트의 핵심 판단 기준은 실험 횟수, 구현량, 모델의 복잡성 또는 에이전트의 작업량이 아니다.

**실제 논문의 원문 정보가 한국어로 얼마나 정확하고 온전하게 전달되는가**다.

이 기준으로 계속 발전시켜라.

우선 현재 시스템과 PDF 6편을 조사하고, 메인 에이전트가 최초의 가설 3개를 선정한 다음, 세 서브 에이전트의 실험을 시작하라.

사용자에게 구현 방법을 선택하도록 반복적으로 질문하지 말고, 실제 실험 근거를 통해 더 좋은 방법을 판단하라.

실행 환경과 작업 범위가 허용하는 동안 위 반복 사이클을 유지하고, 완료 시에는 검증된 성과와 여전히 남아 있는 한계를 명확히 구분하여 보고하라.
