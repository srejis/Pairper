# Pairper UI 전면 개편 — 1차 통합 구현 지시서

## 1. 목표와 기존 문제

Pairper는 사용자가 PDF 논문을 등록하고, ChatGPT가 로컬 MCP를 통해 논문 구조를 재구성한 후, 이를 편하게 읽는 Windows 데스크톱 프로그램이다.

현재 구현은 React + TypeScript 프론트엔드를 사용하지만, 논문 라이브러리와 리더가 상시 좌우로 나뉘고 PDF 추가, MCP 상태, 연결 진단, 재연결, 설정이 모두 상단에서 경쟁한다. 결과적으로 핵심 기능인 논문 읽기에 충분한 공간과 시각적 집중도가 확보되지 않았다.

이번 작업에서는 라이브러리와 읽기 화면을 완전히 분리하고, 문서 중심의 미니멀한 UI로 전면 개편한다.

사용자는 지금까지 논의한 추천 디자인을 **모두 1차 기본안으로 채택**했다. 세부 디자인을 다시 묻지 말고 구현을 진행한다. 이후 실제 사용 피드백에 따라 개별 요소를 수정한다.

대상 저장소: `srejis/Pairper`

검토 기준 커밋: `0504180ffdff87d754a119093931e6ca5b9a5fe4`

## 2. 반드시 보존할 기능

- 기존 Python PDF 추출 및 SQLite 라이브러리
- 원본 PDF, SHA-256, span ID, 좌표, 문서 블록 참조
- 로컬 MCP 11개 도구와 Secure MCP Tunnel 연결
- 시스템 트레이 상주 및 자동 재연결
- Windows 로그인 자동 시작 설정
- QtWebEngine + WebChannel 구조
- React + TypeScript 렌더러
- 문서 블록 12종, KaTeX 수식, 표 병합 셀, 그림 및 원본 이미지 fallback
- 원본 충실도 검증 및 텍스트 연결 이력

UI 개선을 위해 기존 문서 스키마나 MCP 프로토콜을 불필요하게 변경하지 않는다.

한국어 번역, AI 설명, AI 채팅 패널은 이번 범위에서 제외한다.

## 3. 디자인 시스템

다음 값을 기본 디자인 토큰으로 사용한다.

| 토큰 | 값 |
|---|---|
| 앱 배경 | `#F5F6F5` |
| 리더 외부 배경 | `#EDF0EE` |
| 문서·패널 표면 | `#FFFFFF` |
| 기본 본문색 | `#293630` |
| 보조 텍스트 | `#738078` |
| 구분선 | `#E1E6E2` |
| 브랜드 색 | `#285745` |
| 선택·강조 배경 | `#E7F1EA` |
| 경고 및 처리 대기 | 절제된 황갈색 계열 |

UI는 과도한 카드, 큰 그림자, 진한 테두리, 다수의 상태 배지 없이 구성한다.

영문과 숫자는 Inter, 한국어는 Pretendard 중심으로 표시한다. 실제 앱에서 해당 폰트를 사용할 수 있도록 로컬 자산 번들링과 폴백 체계를 구성한다. 외부 CDN 연결에 의존하지 않는다.

폰트 파일을 저장소에 추가할 때 라이선스와 배포 조건을 확인한다.

논문 수식은 기존 KaTeX 서체를 유지한다.

모든 컴포넌트의 간격, 크기, 색상을 CSS 변수로 통일한다.

## 4. 앱의 화면 구조 변경

현재 `App.tsx`의 라이브러리와 리더 동시 배치 구조를 제거한다.

최상위 화면 상태를 다음과 같이 구성한다.

- `library` — 논문 목록
- `reader` — 특정 논문의 읽기 화면

별도의 라우터 라이브러리는 꼭 필요하지 않다. 현재 QtWebEngine 구조에 맞게 안전한 React 상태 기반 화면 전환을 우선 사용한다.

초기 실행은 라이브러리 화면이다.

읽기 가능한 논문을 선택하면 리더로 전환하고, 리더의 왼쪽 상단 버튼을 누르면 라이브러리로 돌아온다.

MCP와 Qt 애플리케이션의 생명주기는 화면 전환과 무관하게 유지한다.

## 5. 라이브러리 화면

### 전체 구성

1280×850px을 기본 설계 기준으로 한다.

- 상단 헤더: 60px
- 중앙 콘텐츠 최대 너비: 1040px
- 본문 시작 여백: 약 36px
- 하단 고정 상태 메시지 제거
- 중앙 콘텐츠 정렬

헤더 왼쪽에는 Pairper 브랜드를 표시한다.

오른쪽에는 설정 버튼과 강조된 `PDF 추가` 버튼만 배치한다.

MCP 연결 진단, 재연결, 긴 기술 상태 문구는 헤더에서 제거한다.

### 제목 및 검색

상단에 `내 라이브러리` 제목과 등록 논문 수를 표시한다.

그 아래에는 검색창, 정렬, 필터 버튼을 한 줄로 배치한다.

검색창은 제목과 파일명을 대상으로 작동한다.

정렬 기본값은 `최근 추가순`이다. 제목순 및 오래된 등록순도 제공한다.

상태 필터는 별도 아이콘 버튼 안의 팝오버에 배치한다.

필터 선택지는 기본적으로 전체, 읽기 가능, 처리 필요, 검토 필요로 구성한다.

검색·정렬·필터를 함께 적용할 수 있어야 한다.

검색 결과가 없으면 간결한 빈 상태를 표시한다.

### 논문 목록

각 논문을 약 80px 높이의 행으로 렌더링한다.

행의 구성은 다음과 같다.

1. 왼쪽 42px 문서 아이콘
2. 제목: 14–15px, 최대 2줄
3. 파일명과 페이지 수: 12px
4. 오른쪽의 작은 처리 상태 아이콘과 텍스트
5. 끝의 화살표 또는 펼치기 표시

행 사이에는 옅은 1px 구분선만 사용한다.

논문 제목 메타데이터가 존재하지 않으면 실제 파일명을 사용한다. 제목, 저자, 발행 연도 등을 임의로 생성하지 않는다.

### 논문 상태별 동작

유효한 저장 뷰가 있는 논문은 행 클릭 시 리더로 이동한다.

뷰가 없는 논문은 라이브러리 안에서 해당 행을 확장한다.

확장 영역에는 다음 내용을 제공한다.

- 현재 처리 상태
- 원본 PDF 등록 여부
- 재구성된 읽기용 문서가 없다는 설명
- ChatGPT에 `Pairper 논문 업데이트해 줘`라고 요청하는 방법
- 요청 문구 복사 버튼
- 실제 오류 정보가 있을 경우 간결한 오류 안내

GPT를 호출하지 않고 단순히 행을 펼쳤다는 이유로 작업이 시작되었다고 표시하지 않는다.

작업 진행률을 실제로 알 수 없다면 퍼센트나 가짜 진행 막대를 만들지 않는다.

완료 상태 판단은 단순 문자열보다 `has_view`와 저장 뷰 유효성을 우선한다.

기존 작업 및 오류 상태에 필요한 정보가 UI용 모델에 부족하다면 Python의 저장소 조회를 읽기 전용으로 확장하되, 없는 정보를 추정해서 표시하지 않는다.

## 6. 논문 읽기 화면

### 상단 툴바

높이 56px의 고정 툴바를 사용한다.

왼쪽: 라이브러리 복귀 버튼

가운데: 현재 논문 제목. 길면 말줄임 처리

오른쪽: 목차, 글자 설정, 기타 메뉴

읽기 화면에는 PDF 추가, MCP 연결 진단, 재연결, 시스템 설정을 상시 노출하지 않는다.

### 본문 영역

전체 배경은 `#EDF0EE`를 사용한다.

문서 영역은 흰색이며 가운데 정렬한다.

문서 최대 너비는 860px, 내부 좌우 여백은 기본 72px로 구성한다.

본문 크기는 17px, 줄 간격은 1.8로 한다.

섹션 제목은 약 23px semibold, 캡션은 약 13–14px로 구성한다.

그림과 표는 사용 가능한 문서 너비를 활용한다. 큰 표와 수식에는 해당 블록 내부 가로 스크롤을 제공한다.

전체 논문은 하나의 연속된 1열 문서로 표시한다.

페이지마다 A4 테두리나 분리된 종이 그림자를 생성하지 않는다.

### 본문 글자 설정

상단 글자 설정 버튼에서 작은 팝오버를 연다.

기본은 글자 크기 감소, 증가, 기본값 복원만 제공한다.

기본 17px, 조절 범위 15–21px, 단계 1px을 권장한다.

글자 설정을 변경해도 원문 참조, 수식, 표, 그림의 내용은 변하지 않아야 한다.

설정은 사용자의 로컬 UI 환경에 저장할 수 있으나 API 키와 혼합하지 않는다.

## 7. 오른쪽 공용 슬라이드 패널

목차와 원본 대조는 동일한 오른쪽 패널 공간을 사용한다.

패널은 기본적으로 닫혀 있다.

너비는 약 320px로 한다.

본문 위에 덮어 표시하는 오버레이 방식을 사용한다.

열고 닫을 때 문서의 너비와 줄바꿈이 바뀌지 않아야 한다.

본문 스크롤 위치도 유지한다.

전환 애니메이션은 약 180–220ms의 절제된 움직임을 사용한다.

화면 너비가 좁은 경우에도 동일한 오버레이 방식으로 동작하도록 한다.

패널은 목차 모드와 원본 대조 모드 중 하나만 활성화한다.

ESC, 닫기 버튼, 적절한 바깥 영역 클릭으로 닫는다.

### 목차 모드

실제로 저장된 `heading` 블록에서 목차를 생성한다.

제목 텍스트는 기존 Python 표시 모델에서 해석한 값을 사용한다.

목차 항목은 heading level에 따라 들여쓰기한다.

항목을 클릭하면 해당 블록으로 스크롤한다.

현재 읽는 섹션은 옅은 녹색 배경 또는 왼쪽 강조선으로 표시한다.

목차를 다시 열었을 때 현재 위치에 해당하는 항목을 확인할 수 있어야 한다.

문서 구조에 heading이 없다면 가상 목차를 만들지 않는다.

### 원본 대조 모드

사용자가 특정 문단·수식·표·그림 블록에서 `원본 확인`을 선택하면 오른쪽 패널을 원본 대조 모드로 연다.

본문에서는 해당 블록에 얇은 녹색 왼쪽 강조선을 표시한다.

오른쪽 패널에는 다음을 제공한다.

- 원본 PDF의 해당 영역 이미지
- 페이지 번호
- 확대·축소
- 여러 페이지나 여러 원본 영역에 걸친 블록의 경우 영역별 탐색

원본은 등록된 PDF의 실제 좌표를 기준으로 가져온다.

기존 코드의 표시 모델에는 텍스트 참조별 page/bbox가 존재하고, 시각 블록에는 원본 영역 정보를 갖는 구조가 있다.

다만 현재 `presentation.py`는 시각 블록의 원본 region을 프론트엔드에 명시적으로 전달하지 않고, `ui/bridge.py`에도 선택 블록의 원본 영역을 조회하는 기능이 없다.

이를 보완한다.

Python에서 저장된 문서 블록의 실제 `region`과 `source_refs`를 기반으로 원본 위치를 검증하고, 해당 PDF 영역을 PyMuPDF로 렌더링해 제공한다.

한 문단이 여러 줄, 2단 레이아웃의 여러 영역, 여러 페이지에 걸치면 단순히 거대한 bbox 하나로 합쳐 주변의 무관한 본문까지 포함하지 않는다. 실제 텍스트 영역과 페이지를 구분하여 적절한 영역 단위로 제공한다.

추출 좌표나 원본 PDF가 유효하지 않으면 이미지를 추측하거나 잘못된 페이지로 연결하지 않고 오류 상태를 표시한다.

프론트엔드에서 임의 파일 경로나 임의 PDF 좌표를 조합해 Python에 명령을 전달할 수 없게 한다. UI는 유효한 paper ID, view ID, block ID 또는 서버가 생성한 제한된 영역 식별자만 요청한다.

응답 이미지 크기와 해상도를 제한하고, 로컬 원본 파일 외 접근을 막는다.

## 8. 원본 확인 버튼의 표시 방식

본문 모든 블록 아래에 항상 별도 버튼을 배치하지 않는다.

마우스가 블록 위에 올라오거나 키보드로 해당 블록에 초점이 이동하면 작은 `원본 확인` 버튼을 표시한다.

터치 및 키보드 접근성이 없는 hover 전용 구현은 피한다.

원본 확인 가능 여부는 유효한 참조 정보가 있는지를 기준으로 판단한다.

원본 확인 기능은 문단·수식·표·그림·캡션·목록 등 실제 참조가 존재하는 블록에 적용할 수 있다.

선택된 블록의 강조 상태는 원본 대조 패널을 닫으면 해제한다.

## 9. 설정 화면 및 알림

상단 설정 버튼을 누르면 앱 설정 화면 또는 패널을 표시한다.

최소한 기존 기능을 유지한다.

- Windows 로그인 시 자동 실행
- MCP 연결 상태
- 다시 연결
- 연결 진단

정상 상태에서는 기술적인 로그와 마지막 도구 호출 정보를 상시 표시하지 않는다.

오류가 발생하면 필요한 수준의 간결한 메시지를 표시하고, 자세한 내용은 설정에서 확인하도록 한다.

PDF 등록 성공, 실패, UI 오류는 일정 시간이 지나면 사라지는 가벼운 알림을 활용한다. 중요한 실패는 사용자가 확인할 수 있도록 남긴다.

기존의 상시 하단 상태 표시줄은 제거한다.

트레이 동작과 백그라운드 MCP 자동 재연결은 그대로 유지한다.

## 10. 접근성 및 화면 적응

키보드로 논문 행, 필터 버튼, 읽기 툴바, 목차, 원본 확인에 접근할 수 있어야 한다.

팝오버와 슬라이드 패널에는 적절한 접근성 레이블을 적용한다.

패널을 닫으면 사용자가 이전에 조작한 버튼이나 블록으로 포커스를 복귀시킨다.

창이 좁아지면 문서 내부 여백을 줄이되 1열 문서 구조는 유지한다.

최소 가로폭에서도 상단 도구가 겹치지 않도록 일부 항목을 더보기 메뉴로 이동한다.

화면 크기를 바꾸어도 논문의 실제 내용과 순서는 바뀌지 않는다.

## 11. 구현 파일과 책임 분리

기존 `frontend/src/App.tsx`에서 모든 화면 상태와 연결 설정 로직을 계속 누적하지 않는다.

화면 단위로 컴포넌트를 분리한다.

권장 구조:

- `frontend/src/components/library/` — 검색, 정렬, 필터, 논문 행 및 확장 영역
- `frontend/src/components/reader/` — 읽기 툴바, 문서 컨테이너, 목차, 원본 대조 패널, 글자 설정
- `frontend/src/components/settings/` — 자동 실행 및 연결 관리
- `frontend/src/components/common/` — 버튼, 아이콘, 팝오버, 알림 등 공통 요소
- `frontend/src/styles/` — 디자인 토큰과 화면별 스타일

기존 문서 블록 렌더러는 재사용한다. 블록 종류와 원문 해석을 재작성하지 않는다.

백엔드에서 필요한 최소한의 표시 데이터와 원본 영역 조회 기능만 안전하게 보완한다.

## 12. 검증

기존 테스트를 통과해야 한다.

추가로 다음을 확인한다.

- 라이브러리와 읽기 화면의 완전한 분리
- 검색·정렬·필터 조합
- 미처리 논문의 인라인 확장
- 뷰가 있는 논문의 읽기 화면 이동
- 목차 이동과 현재 섹션 강조
- 패널을 열고 닫은 뒤 스크롤 및 줄바꿈 유지
- 글자 크기 조절 및 복원
- 여러 PDF 영역과 페이지에 걸친 원본 대조
- 수식·표·그림 fallback 보존
- 키보드 접근성과 포커스 복귀
- 원본 PDF 및 SQLite 데이터 보존
- 트레이와 MCP 자동 연결의 회귀 방지

실제 논문 재구성 뷰가 없는 경우에는 별도 합성 테스트 문서로 읽기 화면의 UI를 검증할 수 있지만, 이를 실제 arXiv 논문 전체의 원문 충실도 검증으로 간주하지 않는다.

1280×850px과 좁은 창 크기의 화면 캡처를 생성하여 결과를 검토한다.

## 13. 완료 보고

변경한 파일, 컴포넌트 구조, 테스트 결과, 실제 화면 캡처, 기존 기능과의 호환성, 원본 대조 기능의 검증 범위, 아직 해결되지 않은 문제를 보고한다.

특히 앱의 실제 시작, PDF 추가, 기존 라이브러리 데이터 유지, MCP 연결 상태를 확인한다.

이번에는 사용자가 세부 디자인을 추가로 선택하도록 요청하지 않는다. 위 기본안을 일관되게 구현하고, 결과물을 보여준 뒤 수정 의견을 받는다.
