# 한국어 번역 실행 시스템

현재 원문 뷰를 입력으로 프로그램이 작업 분할·문맥/원본 이미지 제공·실제 AI 호출·별도 원문 대조·수정·재검증을 관리한다. AI가 작성한 예시 번역을 내장하거나 이전 한국어 결과를 새 실험에 주입하는 방식이 아니다. Python 안에 번역 모델이 내장되는 것은 아니며, 설치된 Codex CLI와 기존 ChatGPT 로그인이 필요하다. 별도 API 키를 추측하거나 MCP 연결 키를 모델 인증으로 사용하지 않는다.

## 실행

```powershell
pairper-translate <paper_id> --experiment <새-실험-이름> --publish
pairper-translate --all --experiment <새-실험-이름> --workers 2 --publish
```

동일한 원문과 실험 이름을 다시 실행하면 완료한 작업을 보존하고 이어서 실행한다. 다른 새 실험 이름은 빈 번역 세션으로 시작한다. 이전 결과가 이미 들어 있는 외부 세션을 새 실행으로 가져오려 하면 거부한다. `--directory`로 번역·실행 이력을 별도 저장소에 둘 수 있다. `--plan-only`는 원문 계획만 확인하며 번역 완료를 뜻하지 않는다. `--max-steps`에 도달한 부분 실행은 미완료로 종료한다.

프로그램은 원본 PDF와 현재 원문 뷰의 해시를 고정한다. 원문만으로 텍스트·수식 내부 자연어·그림 작업을 구성하고, 각 작업의 원본 페이지와 그림 이미지를 실제 호출에 첨부한다. 번역 응답은 원문을 덮어쓰는 문서가 아니다. 본문의 수식 토큰과 표 구조, 수식에서 선택하지 않은 수학 구조, 그림 라벨의 원문 좌표를 보호한다.

전체 후보가 생긴 뒤 새 AI 호출로 각각의 실제 원문/현재 한국어 및 조립 문맥을 검토한다. 이전 검토 판정과 번역자 설명은 검토 프롬프트에서 숨긴다. 구체적인 문제가 있으면 수정 응답을 새로 생성하고 다시 독립 검토한다. 이웃 결과가 바뀌면 해당 검토를 다시 요구한다. 프로토콜/보호 검사에서 거절한 응답도 다음 시도에 오류 근거로 전달한다. 의미 수정과 형식 재시도에는 한도가 있으며, 한도를 넘거나 판독이 불가능하면 `needs_review`로 남긴다.

원문에 실제로 있는 모순·불완전성은 충실하게 보존하고 근거를 기록한다. 사실을 추측해 정상화하거나 원문 자체의 결함을 번역 오류로 둔갑시키지 않는다.

별도 원문 검사에서 교정할 내용이 없다고 확인한 경우에도 실제 관찰과 응답 해시를 저장한다. 같은 원문·작업의 다음 생성/수정 호출에 이 근거를 제공하여 동일한 원문 결함을 추측으로 반복 교정하지 않게 한다. 새로운 번역 검토자에게는 앞선 검사 판정을 노출하지 않으며, 원문 검사 통과를 번역 승인으로 대체하지 않는다.

실행 환경이나 프로그램 오류를 해결한 뒤에는 `--retry-failed "해결한 실행 오류와 재시도 이유"`로 실패 한도를 소진한 작업을 명시적으로 재시도할 수 있다. 후보·검토·거절 응답·의미 수정 횟수와 이전 실패 이력은 보존한다. 의미 수정 한도 초과나 해결되지 않은 원문 판독 문제로 차단된 작업에는 적용하지 않는다.

원문 문제로 차단된 작업은 `--recheck-source "원문을 다시 검사할 이유"`로 별도 PDF 검사를 새로 수행한다. 검사에서 더 이상 교정이 필요하지 않다고 확인해도 번역을 승인하지 않고 새 생성 또는 새 번역 검토를 요구한다. 미해결 문제나 검사 실패는 계속 차단한다. 그림의 원본 이미지는 그대로 표시하며 보조 OCR은 번역 그 자체가 아니다. OCR 차이가 한국어 라벨·값·좌표·본문에 영향을 주는지 검사하고, 출력과 무관하다고 확인한 차이는 근거 메모로 보존한다. 원본 수학·축 눈금은 번역하거나 새로 그리지 않는다.

그림 원문 검사에는 지적을 발생시킨 응답과 실제 현재 후보를 따로 제공한다. 실제 Reader 투영 함수를 통해 내보낼 한국어 목록을 계산하며, 저장돼 있어도 원문·번역이 같은 라벨은 화면 목록에 나오지 않는다는 사실을 근거로 전달한다. 현재 원본 참조의 좌표·글꼴 크기에서 작은 라벨의 확대 영역을 만들고 해상도를 조절한다. 확대 배율·픽셀·개수 한도와 누락도 기록하므로 판독 불가를 임의로 해결했다고 간주하지 않는다.

생성·검토 응답의 `source_concerns`에 구체적인 원문 전사 불일치 의심이 나오면 프로그램이 원본 PDF에서 페이지와 확대 수식 이미지를 새로 만들어 별도 검사에 넘긴다. 실제 원문 run의 각주·서식 정보를 함께 제공하여 평문 표현만 보고 정보 누락으로 오인하지 않게 한다. 수식 교정과 잘못 나뉜 연속 run의 재조립 제안은 또 다른 AI 호출로 원본과 대조한 뒤, 전체 원문 검사를 통과한 새 뷰로 저장한다. 원본 PDF·추출 snapshot·이전 뷰와 DB 백업을 보존한다. 재조립은 원문 참조와 순서를 정확히 유지하며 수식 영역은 원본 좌표로 계산한다. 일반 메모와 원문 자체의 결함은 `notes`에 보존하고 불필요한 별도 원문 재검사를 시작하지 않는다. 교정안은 실제 scan이 반환한 정확한 내용만 적용하며 수동 제안을 끼워 넣을 수 없다.

완전한 수식 ID가 특정 원문 단위를 지목하면 그 같은 단위의 현재 수식들도 함께 검사한다. `M0 및 #M1`처럼 같은 문장의 수식을 함께 지적한 경우 한쪽의 현재 값이 검사 범위에서 빠지는 일을 막는다. 다른 단위로 임의 확대하거나 알 수 없는 수식 ID를 인정하지 않으며, 제안의 정확한 현재 값과 실제 변경 여부 검사는 그대로 유지한다.

원문이 교정되면 CLI는 기존 한국어 후보를 가져오지 않고 새 원문에 대해 빈 세션에서 다시 시작한다. 한 번 실행에서 원문 재시작은 세 번으로 제한한다. 자동으로 안전하게 교정할 수 없는 원문 문제는 후보를 승인하지 않고 즉시 `needs_review`로 남긴다. MCP 실행이 `source_changed`로 끝나면 같은 실험 이름으로 시작 도구를 다시 호출해 새 원문의 빈 실행을 생성한다.

원본의 코드 문자 판독에는 PDF 글꼴의 Encoding·ToUnicode 및 실제 glyph 관찰을 제한된 범위에서 제공한다. PDF 내부 문자 코드와 Unicode, glyph ID를 구분하며, 글꼴의 역매핑 후보를 실제 원시 텍스트 연산자 확인으로 과장하지 않는다. PDF·추출 snapshot·현재 뷰의 해시를 결부하고 누락·크기 제한·판독 불가를 기록한다. 생성·수정·새 독립 검토는 같은 중립적인 원본 근거를 받으며, 새 검토에 이전 scanner의 결론을 주입하지 않는다. 원문에 실제 인쇄된 비정상적인 코드 구분 문자를 관례에 맞춰 고치지 않는다.

수식 끝 조각이 바로 앞뒤 문단에 잘못 소속된 경우에는 제한적인 `math_boundary_transfer`를 지원한다. 같은 페이지에서 인접한 기존 수식과 문단 가장자리의 수학 run만 대상으로, 원래 수학 문자열을 수식의 한 위치에 그대로 한 번 삽입하고 양쪽 참조를 원자적으로 이동한다. 원본 span 좌표로 영역과 새 자산 참조를 계산하며, 전체 참조 수·유일 소유·순서·나머지 문장과 메타데이터를 보존한다. 겹치는 교정이나 다른 원문 침범은 거부한다. 전체 변경 전후 두 블록을 별도 PDF 검토자가 확인하고 전체 원문 검증·새 뷰 저장을 통과해야 빈 번역으로 다시 시작한다. 이 경로도 실제 source scan의 제안만 적용한다.

병렬 실행 중 다른 작업자가 현재 원문을 교정하면, 예외 문구를 추측하지 않고 실제 PDF·snapshot·뷰 ID·뷰 해시를 이전 저장 출처와 대조한다. 유효한 새 원문이 확인된 실행만 `source_changed`로 전이하고 이전 lease를 해제하며 후보·검토·이력은 보존한다. CLI는 같은 재시작 한도 안에서 빈 새 세션으로 이어간다. MCP 실행·상태 조회도 해당 전이를 감지하며, 새 실행 시작은 기존 MCP 계약대로 같은 실험의 시작 도구를 다시 사용한다. 무관한 오류·손상된 원본·확정된 결과는 이 복구로 숨기거나 바꾸지 않는다.

원문 문자 매핑의 목록 순서는 프로세스의 임의 hash seed에 의존하지 않도록 정렬한다. 같은 PDF 관찰값이 다른 목록 순서로 제공돼 검토 해시만 달라지는 불필요한 반복을 막는다. 서로 다른 프로세스와 실제 PDF에서 동일한 근거 JSON을 검증하며, 실제 후보·문맥·원문 값의 변화는 계속 새 검토를 요구한다.

작업 선택 전 후보 정규화와 PDF 문자 근거의 캐시는 짧은 읽기 snapshot을 닫은 뒤 쓰기 잠금 밖에서 준비한다. 이 준비는 작업 점유나 검토 승인이 아니다. 실제 작업 선택은 기존 쓰기 transaction 안에서 현재 원문·후보·lease·검토 해시를 다시 검사하므로, 준비 중 다른 작업자가 내용을 바꿔도 이전 snapshot을 승인하지 않는다.

원문 교정 제안이 독립 PDF 검토에서 거절되면 아직 적용하지 않은 전체 제안과 실제 지적을 다음 제안자에게 전달한다. 최초 제안을 포함해 최대 세 번 전체 배치를 새로 검토하며, 새 검토자에게는 이전 판정과 지적을 숨긴다. 이전 문제를 누락하거나 해결 불가로 남긴 제안은 적용하지 않는다. 한도를 소진하면 부분 적용 없이 품질 차단으로 기록하고 일반 실행 오류 재시도로 이 한도를 초기화하지 않는다. 각 제안·검토·적용의 파일과 해시를 연결해 보존한다.

그림에 소속된 원문 참조의 글꼴 경계 상자가 그림 영역에 일부 걸치면, 검토 근거 이미지는 두 영역의 교집합에서만 만든다. 원래 경계·실제 사용 경계·잘림 가능성을 함께 기록한다. 그림 원문 영역과 후보를 바꾸지 않으며, 다른 그림 참조나 완전히 바깥에 있는 영역·사용자가 제안한 범위 밖 좌표는 계속 거절한다. 글꼴 경계의 잘림 표시는 실제 글자 잉크 누락을 확정하는 판정이 아니다.

본문 수학 토큰 끝의 실제 마침표 바로 뒤에 한국어가 붙으면 원문 수식은 유지한 채 후보를 거절한다. 새 생성·수정 호출은 오류 근거를 받아 주변 문장을 다시 구성하고 독립 검토를 거친다. 저장된 후보와 정규화 캐시에도 같은 검사를 적용하며, 기존 의미 수정 횟수와 실패 이력은 지우지 않는다. 이 검사는 직접 붙은 문자 경계만 검사하므로 공백을 끼운 어색한 문장이나 추가 해설은 별도 의미 검토가 계속 필요하다.

## 원문을 보존하는 수학 경계 계약 V2

하나의 보호 수식에 문장 마침표·확률·다음 문장 주어가 함께 묶이면 한국어 조사를 자연스러운 위치에 넣기 어려울 수 있다. 새 실험에 `--math-partition-v2`를 지정하면 한국어 생성 전에 원문만으로 경계를 검사한다.

```powershell
pairper-translate <paper_id> --experiment <새-V2-실험-이름> --math-partition-v2 --publish
```

전체 인라인 수식 목록을 빠짐없이 분류하고 어휘 경계의 구두점 후보를 제한된 배치로 나눈다. 원본 PDF를 첨부한 실제 AI 제안과 별도 새 PDF 검토가 모두 통과해야 빈 번역 세션을 만든다. 검토자는 제안자의 설명·판정과 기존 한국어를 받지 않는다. 수학적 쉼표와 서술 경계의 구분은 별도 원문 판정이며, 구두점이 있다는 이유만으로 분할하지 않는다.

분할은 번역용 계약이다. 원문 Document·LaTeX·refs·자산은 그대로 보존한다. 조각의 전량·순서·연속 범위·원문 재결합·현재 KaTeX 구조 동일성을 검사하고, 프로그램이 만든 조각 식별자만 번역에 제공한다. 누락·중복·다른 단위의 조각·순서 변경을 거절한다. 실제 Reader 투영에도 같은 계약을 적용하며 전체 부모 수식 이미지를 각 조각의 대체 이미지로 반복 표시하지 않는다. 실제 화면의 수식 표시 검사는 별도로 필요하다.

이미 원문 계약에 자연어 노드가 등록된 수식은 기존 MathRole/Overlay 작업으로 명시 분류한다. 원문 SHA와 노드 목록을 대조하며 새 기호 분할에서 제외해도 기존 생성·독립 검토를 생략하지 않는다. 전체 인라인 수식 목록은 새 기호 후보·기존 자연어 경로·비후보·미지원으로 빠짐없이 집계한다.

원문·실험 이름·계약 버전에 묶인 계획과 실제 호출 증거는 번역 저장소의 `math-partitions`에 보존한다. 완성 전 재시도마다 별도 시도 디렉터리에 이미지와 호출을 보관하여 이전 요청의 첨부 자료를 덮어쓰지 않는다. 완성된 계획의 안정적인 캐시 이름은 유지한다. 캐시를 사용할 때도 요청·프롬프트·스키마·원응답·실제 이미지 인자·해시와 독립 검토를 다시 검증한다. 원문이 바뀌면 새 계획을 검토한 뒤 빈 번역으로 시작한다. 기존 실행의 수정 한도나 한국어를 새 계약으로 옮기지 않는다. 이 경로는 실제 AI 호출이 필요하므로 `--plan-only`와 함께 사용할 수 없다.

독립 원문 검토가 제안을 거절하면 실제 미적용 제안과 지적을 다음 원문 제안자에게만 전달한다. 전체 묶음을 다시 제안하고 새로운 독립 검토를 받으며 최초를 포함해 최대3회다. 새 검토자는 이전 지적·판정을 받지 않는다. 원문·선택·초기 프롬프트에 묶인 체인에 예약한 회차와 실제 호출·거절·수정 근거를 저장하므로 재시작이 횟수를 초기화하지 않는다. 이미 통과한 묶음도 같은 원문과 실제 호출 파일·이미지를 모두 재검증한 경우에만 이어 쓴다.

MCP에서는 `start_translation_workflow(..., math_partition_v2=true)`가 원문 계획 작업 ID를 즉시 반환한다. 상태 도구의 `ready_run_id`가 생긴 뒤 해당 실행을 진행한다. 계획과 번역 실행을 합쳐 최대4개 작업자이며 취소는 실제 호출에 전달된다. 기록된 실제 호출 실패·취소는 CLI의 `--retry-failed REASON` 또는 MCP 시작 도구의 `source_planning_retry_reason`으로 명시 재시도할 수 있다. 실패 근거를 재검증하며 회차와 이전 이력을 보존한다. 품질 검토3회 소진·검토 거절은 이 실행 복구로 해제하지 않는다. 검증할 수 없는 중단 상태도 임의로 비우지 않는다. 계획 실패나 판독 불가는 번역 승인으로 바꾸지 않는다. 기존 기본 계약은 그대로 사용할 수 있다.

## 연결된 AI에서 실행

MCP의 `start_translation_workflow`, `run_translation_workflow`, `get_translation_workflow_report`, `finalize_translation_workflow`를 사용한다. 실행 도구는 백그라운드 작업을 시작하고 즉시 반환하며 상태 도구로 진행/차단 사유를 확인한다. `cancel_translation_workflow`는 실제 AI 프로세스에 취소를 전달하고 이미 저장한 작업과 이력을 유지한다. 재개는 같은 실험으로 다시 실행한다.

기존 개별 번역 도구는 진단과 명시적인 수동 작업용으로 유지한다. 그 도구로 사례를 직접 고친 사실은 이 실행 시스템의 새 실험 성공을 대체하지 않는다. 오래 실행 중인 MCP 서버는 새 도구 등록을 위해 다시 시작해야 할 수 있다.

## 이력과 완료의 의미

번역 저장소의 `workflow/workflow.db`에 작업별 출처·상태·lease·후보·검토·수정 전후·거절/실패 이력을 저장한다. `workflow/runs`에는 실제 원문 요청, 모델에 보낸 프롬프트/스키마/이미지 해시, 원본 응답, 실행 도구/모델 선택 근거, 사용량과 오류를 보존한다. 원문이 바뀌거나 오래된 응답이 도착하면 현재 결과의 검토로 받아들이지 않는다. 실행 중 다른 경로가 세션을 편집하면 덮어쓰지 않는다.

모든 작업의 현재 원문 대조와 기존 전체 문서 검사를 통과해야 `--publish` 또는 확정 도구가 로컬 불변 revision을 만든다. 인터넷 발행이 아니다. `ready`/`published`는 실행·저장 계약 상태이며 번역의 절대 무오류 증명은 아니다. 같은 모델 계열의 비맹검 검토라는 한계를 유지하고 실제 읽기 화면도 별도로 확인한다. 실패한 모델 호출·합성 회귀검사·실제 논문 실행은 구분해 보고한다.
