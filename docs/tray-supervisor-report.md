# 단일 트레이 앱 및 MCP 자동 재연결 결과

작업일: 2026-10-16 (Asia/Seoul). 지시문은 `프롬프트/2026-10-16_단일-트레이-상주-및-MCP-자동재연결_구현지시서.md`에 UTF-8로 보관했습니다.

## 변경한 구조

Pairper 데스크톱 프로세스가 `ApplicationController`를 통해 단일 창, 시스템 트레이, `TunnelSupervisor`를 소유합니다. React의 화면 수명은 연결을 시작하거나 종료하지 않습니다. 기존 Python PDF/SQLite/문서 처리와 stdio MCP 프로토콜 및 11개 도구는 유지했습니다.

- `app/controller.py`: 트레이 아이콘·열기/상태/다시 연결/종료 메뉴, 더블클릭 복원, 최초 1회 숨김 안내, 트레이 불가 시 정상 종료 대체.
- `app/instance.py`: 현재 사용자만 접근하는 QLocalServer IPC와 프로젝트별 QLockFile. 두 번째 프로세스는 기존 창 활성화 메시지와 ACK를 주고받고 종료합니다. 프로세스 이름으로 검색·종료하지 않습니다.
- `tunnel/session.py`: 기존 프로필·환경 격리·마스킹·프로세스 잠금·Windows Job Object를 공통 세션으로 재사용합니다. 앱과 개발용 CLI가 같은 세션 구현을 사용합니다.
- `tunnel/supervisor.py`: 별도 작업 스레드가 프로세스 생존과 루프백 health/readiness를 10초 간격으로 검사합니다. 프로세스 종료와 영구 오류 로그는 더 빠르게 감지하되 HTTP 검사 주기는 유지합니다.
- `ui/window.py`, `legacy_window.py`: 컨트롤러가 있는 앱에서 X는 숨김, 명시적 종료 후에만 화면 자원을 정리합니다. 컨트롤러 없이 실행하는 렌더러 테스트 창은 기존 닫기 동작을 유지합니다.
- `ui/bridge.py`, React: 캐시된 안전한 연결 스냅샷과 상태 변경 신호, 제한된 `reconnectTunnel`을 제공합니다. 프론트엔드에 키/터널 ID/임의 명령을 넘기지 않습니다.

## 재연결과 종료 정책

상태는 `not_configured`, `connecting`, `connected`, `disconnected`, `reconnecting`, `authentication_failed`, `error`, `stopped`로 구분합니다. `connected`는 로컬 런타임 준비를 뜻합니다. 원격 도구 이름과 시각은 별도 기록입니다.

health/readiness 연속 3회 실패 또는 프로세스 종료 시 기존 소유 프로세스 트리를 정리한 다음 재연결합니다. 한 번의 검사 실패는 즉시 재시작하지 않습니다. 재시도 간격은 3·5·10·20·40·60초에 ±10% 지터를 적용하며 최대 60초입니다. 60초간 안정 연결을 유지하면 횟수를 초기화합니다. 키/권한/Tunnel ID/필수 파일·실행 파일 오류는 자동 재시도를 멈추고 수동 “다시 연결”을 기다립니다.

명시적 종료는 재시도 취소 → 작업 스레드의 소유한 tunnel-client 및 MCP 자식 종료 → Job Object 활성 프로세스 0 확인 → 창 자원/트레이/IPC 정리 → QApplication 종료 순서입니다. GUI 스레드에서 터널 실행이나 종료 대기를 하지 않습니다. 원본 PDF, SQLite 데이터, 기존 뷰는 삭제하지 않습니다.

## 실제 Windows·원격 연결 검증

실제 `.env`와 기존 등록 논문을 사용했으며 인증값은 출력하거나 변경하지 않았습니다. 시스템 시작 작업은 등록·변경하지 않았습니다.

| 항목 | 관측 결과 |
| --- | --- |
| 시스템 트레이 | 실제 Windows에서 사용 가능, 아이콘 표시 확인 |
| 최초 앱 실행 | 논문 목록 창 표시와 터널 자동 시작 확인 |
| X 버튼 | 창 숨김, 트레이 유지, 감독자 연결 유지 |
| 숨김 중 원격 MCP | 연결된 Pairper 도구로 `list_papers` 성공, 기존 논문 1편 조회 |
| 단일 실행 | 두 번째 `python -m pairper.app.main --tray` 종료 코드 0, 기존 창 복원, 터널 PID 동일 |
| 강제 장애 | 소유한 tunnel-client PID 60708 종료 후 새 PID 61672로 자동 복구 |
| 복구 후 원격 MCP | 창 숨김 중 목록 1편 조회 및 `get_page_image`의 PNG 이미지 응답 확인 |
| 수동 재연결 | 기존 PID 61672 정리 후 새 PID 57420으로 연결 |
| 명시적 종료 | 감독자 `stopped`, 트레이 제거, 소유한 프로세스 트리 정리 확인 |
| 데이터 보존 | 실행 전후 논문 ID·원본 SHA-256·현재 뷰 ID 동일 |

첫 관측에서 이전 분리 실행기는 이미 종료되어 있었고 원격 MCP는 “최근 300초간 클라이언트 확인 없음”으로 실패했습니다. 새 앱 자동 연결 후 위 원격 호출들이 성공했습니다. 프로세스 장애 복구와 실제 원격 호출을 모두 확인했으며, readiness만으로 성공을 추정하지 않았습니다.

## 자동 시작

새 작업 이름은 `Pairper`이며 `start-pairper.ps1 -Tray`를 실행합니다. 현재 사용자 로그인, 기본 20초 지연, 일반 권한, 중복 실행 무시, 앱 비정상 종료 시 1분 간격 최대 3회 재시작, 실행 시간 제한 없음입니다. 앱 내부 터널 재연결과 작업 스케줄러의 앱 재시작은 별개입니다.

`install-pairper-autostart.ps1 -ValidateOnly`로 실제 작업 객체 설정을 확인했습니다. 기존 `Pairper MCP Tunnel` 작업은 등록되어 있지 않았습니다. 설치/이전 작업 전환은 사용자가 명시적으로 스크립트를 실행할 때만 수행하도록 했습니다. 기존 작업이 있으면 소유권을 확인하고 `-MigrateLegacyTunnelTask`를 지정했을 때만 비활성화/실행 중지를 합니다. 소유권이 불명확한 작업은 변경하지 않습니다.

**아직 미검증:** 실제 로그인 작업 등록·로그아웃/재로그인, 실제 네트워크 어댑터 단절. 사용자 세션을 자동으로 종료하거나 네트워크를 끊지 않았습니다. 일시적 네트워크/readiness 실패와 잘못된 키·권한의 무한 재시도 방지는 테스트용 실패 주입으로 검증했습니다. 실제 자격정보를 일부러 바꾸지 않았습니다.

## 자동화 및 회귀 검증

기존 Python 테스트에 컨트롤러·IPC·감독자 테스트를 추가했습니다. 일시 실패 시 기존 세션 유지, 연속 실패/프로세스 종료 시 재시작, 이전 세션 정리 후 새 세션 시작, 재시도 지터/상한, 안정 연결 후 초기화, backoff 중 취소, 영구 오류 대기와 수동 복구를 검증합니다. Qt 컨트롤러 테스트는 트레이 시작/숨김/복원/명시적 종료/트레이 없는 환경/두 번째 실행을 확인합니다. IPC는 별도 Python 프로세스와 ACK를 교환합니다.

최종 Python 테스트 **58개**, React 테스트 **17개**가 통과했습니다. React 테스트는 기존 12종 블록·fallback·PDF 등록/갱신에 “다시 연결” 요청을 추가했습니다. 별도 QtWebEngine 통합 검증도 통과했습니다(14개 블록, 정상 수식 2개, 오류 수식 fallback 1개, 깨진 이미지 0개, 네이티브 PDF 등록, 재시작 후 14개 블록 복원). Ruff와 TypeScript 검사, Vite 빌드 및 Python 패키지 빌드도 통과했습니다.

논문 재구성·번역·해설 기능을 추가하거나 기존 논문의 뷰를 새로 만들지는 않았습니다. 이번 실제 원격 검증은 읽기 도구만 호출했습니다.
