# Secure MCP Tunnel 및 TypeScript UI 전환 결과

이 문서는 이전 전환 작업의 기록입니다. 현재는 앱이 트레이와 터널을 함께 관리합니다. 최신 구조와 검증 결과는 [트레이·자동 재연결 보고](tray-supervisor-report.md)를 확인하세요.

작업일: 2026-10-15~16 (Asia/Seoul). 사용자 지시문 원본은 `프롬프트/2026-10-15_Secure-MCP-Tunnel_및_TypeScript-UI_수정지시서.md`에 UTF-8 Markdown으로 보관했습니다.

## 구현한 변경

- `.env`를 변경하지 않고 현재 사용자 전용 DACL을 설정했습니다. Git 추적과 이력에 포함된 기록은 없었습니다. `.env`, 파생 환경 파일, `.pairper`, 로그와 자격 파일을 Git에서 제외합니다. `.env.example`만 공유합니다.
- Python의 리터럴 `.env` 파서가 필수 변수와 형식을 검사합니다. 키를 영구 환경변수에 등록하지 않습니다. 다른 프로젝트의 OpenAI/MCP/터널 환경 설정을 제거한 자식 실행 환경에만 프로젝트 값을 전달합니다.
- 기존 Python stdio MCP를 공식 `sample_mcp_stdio_local`과 동일한 `main` 채널로 연결합니다. 프로필은 `.pairper/tunnel-client.yaml`에 저장하며 키는 `env:CONTROL_PLANE_API_KEY` 참조만 기록합니다. JSON 문법의 YAML 1.2 파일입니다.
- 실행 파일은 `-ClientPath`로 지정해 `.pairper/settings.json`에 보관할 수 있습니다. 기본 검색은 저장된 경로 → PATH → 사용자가 알려준 v0.0.16 설치 경로입니다. 실제 설정을 코드에 넣지 않습니다.
- 루프백 동적 포트와 `health.url`, 상태 파일, 마스킹 로그를 사용합니다. `/healthz`와 `/readyz`를 별도로 조회합니다. 실행기는 파일 잠금으로 중복을 막고, Windows Job Object로 부모 종료 시 터널 및 MCP 자식이 남지 않도록 합니다.
- Windows 작업 스케줄러 설치/해제 스크립트를 제공합니다. 현재 사용자 로그인 트리거, 20초 지연, 일반 권한, `IgnoreNew`, 최대 3회/1분 재시작, 실행 시간 무제한 설정입니다. 인증 실패를 발견하면 별도 상태로 기록하고 정상 종료해 같은 키로 무한 재시작하지 않습니다.
- UI와 문서 렌더러를 React + TypeScript + Vite로 전환했습니다. Python의 PDF 처리·SQLite·MCP 11개 도구는 유지합니다. Qt는 데스크톱 셸과 제한된 WebChannel을 담당합니다.
- `document/presentation.py`가 원문 ID를 해석하여 버전이 있는 표시 데이터를 반환합니다. React는 새 문장이나 구조를 추론하지 않습니다. 원본 자산 URL 외 임의 경로는 받지 않습니다. API 키, 터널 ID, 프로필 내용은 WebChannel로 보내지 않습니다.
- 12종 블록, 인라인/블록 수식, 병합 셀, 그림·벡터 영역 이미지, 원본 fallback, 원문 대조, 생략/검토/실패 상태를 보존했습니다. 프로덕션 JS/CSS/KaTeX 글꼴은 Python 패키지에 포함하며 Vite 서버 없이 작동합니다.
- 서로 다른 TextRun 사이의 공백 문제는 Python 공통 텍스트 연결 모듈로 수정했습니다. 명시적 `before` 정책과 원문 좌표를 사용하며, 단어 안의 스타일 경계·기존 공백·문장부호·하이픈을 고려합니다. 변경 이력도 보관합니다. `before`는 기본값이 있는 추가 필드라 기존 1.0 문서를 읽을 수 있습니다.
- Python HTML 렌더러와 이전 Qt 위젯 UI는 제거하지 않았습니다. `--legacy-ui`로 열 수 있고 같은 텍스트 연결 모듈을 사용합니다.

## 실제 연결 검사

| 단계 | 결과 |
| --- | --- |
| 기존 로컬 stdio MCP | 회귀 테스트 통과, 도구 11개 유지 |
| `tunnel-client doctor --explain --json` | 실제 v0.0.16으로 통과 |
| 터널 인증/연결 | 실제 기존 자격정보로 메타데이터 조회 성공, 터널 시작 로그 확인 |
| 로컬 `/healthz`, `/readyz` | 각각 200 응답 확인, 루프백에만 동적 바인딩 |
| 작업 스케줄러 설정 | `-ValidateOnly`로 실행 경로·지연·권한·재시작·중복 설정 확인 |
| 실제 자동 시작 등록 | **수행하지 않음**. 사용자가 설치 스크립트를 실행할 때만 등록하라는 지시를 준수 |
| 로그아웃/재로그인 | **미검증**. 현재 사용자 세션을 종료하지 않음 |
| ChatGPT 도구 발견/조회/이미지/쓰기 | **미검증**. 사용자 설정 화면의 등록 및 실제 요청이 별도로 필요 |

현재 수동 검증용 터널 실행기는 숨김 창으로 시작했습니다. 이것은 Windows 자동 시작 등록과 별개입니다. UI의 “로컬 터널 런타임 준비 완료”는 ChatGPT 호출 성공을 뜻하지 않습니다. 터널 하위 MCP에서 성공한 도구 이름과 시각만 기록하며, 도구 호출자의 제품이 ChatGPT였는지는 로컬 상태로 증명하지 않습니다.

## 검증과 제약

Python 테스트 **34개**, 프론트엔드 컴포넌트 테스트 **17개**를 구성했습니다. 기존 기능과 터널 파서·격리·마스킹·프로필 멱등성·중복 실행·공백 처리·표시 모델·외부 접근 차단·Python HTML과 표시 모델의 텍스트 일치·미검증 표 fallback을 확인합니다. 프론트엔드는 12종 블록, 병합 셀, 수식 fallback, React 이스케이프, 외부 자산 거절, MCP 갱신과 PDF 추가 흐름을 확인했습니다.

QtWebEngine에서 Vite 서버 없는 실제 빌드로 14개 블록/12종 전체, 정상 KaTeX 2개, 오류 수식 원본 fallback 1개, 병합 셀, 깨진 이미지 0개를 확인했습니다. 실제 네이티브 파일 선택기를 테스트용 입력으로 제어해 PDF 추가 버튼 → WebChannel → 원본 등록까지 실행했습니다. 별도 Library 인스턴스의 뷰 확정이 자동 반영되었고, 새 창을 열어 같은 SQLite에서 14개 블록을 복원했습니다. Ruff, TypeScript 검사와 배포 패키지 빌드를 수행했고 wheel의 React UI 포함과 실제 자격정보 미포함을 검사했습니다.

검증 중 Windows에서 JSON 상태 파일을 읽는 순간 `os.replace`가 sharing lock으로 실패하는 것을 발견해 제한된 재시도를 추가했습니다. 또한 v0.0.16의 명령 파서는 백슬래시를 escape로 해석하므로 MCP 명령 경로는 forward slash로 직렬화합니다. 키나 실제 터널 ID를 로그에 출력하지 않습니다.

기존 라이브러리의 `2412.15750v1` 13페이지 원본이 유지되는 것을 확인했습니다. 현재 해당 논문은 뷰 생성 전입니다. 이번 작업에서 실제 논문을 GPT가 새로 분석했다고 주장하지 않으며, 테스트 문서의 UI 통과를 실제 논문 수식·표·읽기 순서 보존 증명으로 보지 않습니다.

후속 검증은 ChatGPT에서 사용자 지정 MCP를 기존 터널에 연결한 뒤 `list_papers` → 페이지 이미지 → 실제 쓰기 순서로 수행해야 합니다. 그 다음 사용자가 설치 스크립트를 실행하고 재로그인 검증을 진행하면 됩니다. 새 AI 분석·번역·설명 기능은 추가하지 않았습니다.
